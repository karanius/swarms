## 5. Representation and Operational Definitions

A transaction is one **graph-scoped center component occurrence with at least one recorded incident edge**. All its incident records must have resolved non-note endpoints, non-Unknown type labels and named source/target handles. Self-loop and unresolved neighborhoods are excluded. This is saved-handle resolution, not declared-port membership, active-output verification or type checking.

| Record | Fields | Meaning |
|---|---|---|
| Neighborhood | graph ID, center occurrence ID/type, binary item set, raw edge witnesses | One scoped transaction; never joins separate component occurrences |
| Edge feature | center type, incoming/outgoing direction, neighbor type, output name, input name | Retains direction and named ports; ignores configuration values and pools versions |
| Association | first feature A, additional feature B, counts, confidence, lifts, graph/group breadth | Observational conditional relationship |
| Example | transaction, source graph, center ID, all matching edge IDs, one preview edge per feature | Preview contains two actual connections and two or three distinct nodes |
| Source | every original URL/path/revision and origin count | Byte deduplication does not discard origins |

Multiple raw edges with one feature count once in the transaction, but every raw witness is retained. Two features may reuse the same outside occurrence; the preview uses the actual identity, not three invented nodes.

For N assessable neighborhoods, n(A) with the first feature and n(A,B) with both, support is n(A,B)/N and observed confidence is n(A,B)/n(A). Center-conditioned lift is confidence divided by n(B)/N_center, where N_center counts assessable neighborhoods of the shared center type. These are positive-count ratios; confidence is not a calibrated behavioral probability. “Without B” means no B record around that assessable center, not that B is impossible.

### Candidate boundary algebra

Given a saved directed graph G=(V,E) and selected occurrence set S ⊆ V:

- Internal edges E[S] = {(u,v)∈E : u∈S ∧ v∈S}.
- Incoming cut δ⁻(S) = {(u,v)∈E : u∉S ∧ v∈S}.
- Outgoing cut δ⁺(S) = {(u,v)∈E : u∈S ∧ v∉S}.
- Outside edges E[V\S] have neither endpoint selected.

The four sets partition source edge records, including parallel records. Unresolved incident records stay flagged. Connectivity is weak connectivity of E[S]; acyclicity is checked separately using a topological traversal. Neither proves semantics, active ports or behavioral correctness. A seed uses actual endpoints of one witness edge per feature; it may have two or three members. Expanding is S ← S ∪ N(S), using recorded immediate neighbors only.

| Candidate field | Stored content | Judgment |
|---|---|---|
| graph, source file hash, source pointer | Exact saved-graph reference | Observed provenance |
| members | IDs, types, versions | Observed scoped identities |
| internal, incoming, outgoing | Full source edge records | Observed topology |
| unresolved | Incident endpoint/handle uncertainty | Unknown boundary completeness |
| unconnectedInputs, terminalOutputs, resources | Declarations, requiredness, dynamic flags; no values | Review obligations / proposed exposures |
| purpose | Editable bounded job statement | Proposed |
| checks | Nonempty, connected, acyclic, readable edges, purpose, configuration, ports, usefulness | No aggregate approval score |
| sources | Every recorded origin | Provenance, not independence |

### Study C data structures

| Record | Fields / meaning | Isolation rule |
|---|---|---|
| Feature fact | (graph-scoped center occurrence, has_feature, feature constant) | One occurrence subject; no type-level subject merge |
| Feature constant | (centerType, direction, neighborType, outputPort, inputPort) | Direction and ports retained; not a component identity |
| Accepted clause | has_feature(X,fB) <= has_feature(X,fA) | Same X, one body atom, distinct known constants, same center type |
| Training rule evidence | Exact body/joint counts, center lift, source-group breadth, witness IDs | Training transactions only |
| Masked case | One hidden feature, all other visible features, source graph/family | Entire target feature removed, not just one duplicate edge |
| Symbolic proposal | Center + fresh neighbor roles, planned ports, training declaration references | Purpose/configuration/aliasing unresolved; no automatic promotion |

This rule language is a relational serialization of the association problem. It is not arbitrary topology or semantic-rule discovery. Shared feature constants would permit cross-center paths in a richer clause language; the accepted one-body same-X clauses forbid that path.
