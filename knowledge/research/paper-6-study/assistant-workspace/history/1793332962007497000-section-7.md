## 7. Implementation and Reproducibility

The implementation consists of a source-preserving extractor, a bounded miner, a separate evidence verifier, a focused visualization and notebook integration. Downloaded node code is never imported or executed; resource values and credentials are not features.

| Artifact | Responsibility |
|---|---|
| `build_topology.py` | Static extraction used by the unchanged corpus overview and pattern study |
| `mine_patterns.py` | Scope/filtering, binary features, provenance unions, FP-Growth, exact scoring and witness catalog |
| `verify_patterns.py` | Separate recount and recorded-edge preview verification against persisted inputs |
| `patterns/index.json`, `all-rules.json`, `rules/`, `transactions.json` | Frozen analysis, complete rule summaries, witness data and transactions |
| `pattern-explorer/` | New interface; existing `corpus-explorer/` remains unchanged |
| `pattern-requirements.txt`, `pattern-environment.lock` | Selected package pins and actual resolved environment |

The API serves a fixed analysis index or a validated rule ID present in the current complete rule list. Old per-rule files from previous runs are not eligible to be served merely because they remain on disk. Source examples load the existing graph-data endpoint. The notebook figure is a local host-owned embed and requires no notebook kernel to explore.

### Study C implementation

The executable cells directly call `relational_experiment.main()`, then `verify_relational.main()`. The saved code is `relational_experiment.py`; artifacts live in `paper-6-corpus/relational/`. Every invocation uses a fresh engine-batch directory and stores source/protocol snapshots, configs, raw rules and logs. Existing rule paths are rejected before launch, preventing failed reruns from accepting stale files. A timeout terminates the process group, with a kill fallback. Freeze metadata pins transaction/training facts, protocol/code, upstream revision and JAR hashes. Raw workflow code and saved configuration values are never executed or inspected.

On this Mac, upstream documents Windows/Linux support rather than macOS support. The native extension was built using a local Apple Clang/OpenMP adapter and installed libomp; the official source was not modified. Native import and fixed-center query application passed. This local compatibility result is not a claim of upstream-supported macOS deployment.
