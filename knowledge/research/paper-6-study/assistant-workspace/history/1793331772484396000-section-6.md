## 6. Rule-Mining Method and Baselines

The implementation uses `mlxtend` FP-Growth on binary sparse neighborhood transactions, followed by one-item-to-one-item association rules. Connection signatures encode their center type, so a co-occurring pair necessarily shares that type; a separate assertion verifies this. The original transaction guarantees the same occurrence, not merely the same type.

| Parameter / control | Fixed value or treatment |
|---|---|
| Minimum joint count | 5 neighborhoods; exact count reasserted after mining |
| Maximum itemset size | 2 |
| Maximum distinct incident features | 24; larger neighborhoods excluded and counted |
| Rule confidence filter | 0; all qualifying directed pair associations retained |
| Catalog display cap | 1,000; all 890 fit in this run; full summaries downloadable |
| Ranking | Joint source-group breadth, joint graph count, joint neighborhood count, confidence, stable ID |
| Confidence denominator | Assessable neighborhoods containing A |
| Lift shown in UI | Within the common center type; pooled engine lift retained separately |
| Connection semantics | Observed target selection plus wiring, not wiring conditioned on target availability |

Earlier association study: gSpan, AMIE, PyClause/AnyBURL, Prolog induction and evolution were not run in that stage. The subsequent bounded PyClause/AnyBURL experiment is now reported as Study C below; gSpan, AMIE, Prolog induction and evolution remain unexecuted.

### Candidate inspection stage after association discovery

Collapse the two directional association summaries into one unordered feature pair for browsing (445 starting pairs). Choose an actual joint witness, seed membership from its recorded endpoints, and compute the entire induced subgraph and its cut. Manual membership changes recompute those records. This is a deterministic inspection mechanism, not another learned rule set or an automatic optimum partition. The original association support remains attached only to the starting pair, never the edited group. No additional mining algorithm comparison has been run.

### Study C: actual PyClause/AnyBURL method

Use the complete frozen assessable transaction set, then split whole recorded source groups by SHA256 of a fixed salt and group ID modulo5. Bucket0 is assessment; all other buckets train. The resulting split has 7548 training neighborhoods from 1020 graphs/170 groups and 710 assessment neighborhoods from 87 graphs/30 groups; group overlap is zero. This is retrospective separation, not pristine held out. Graphs with no assessable transaction do not enter this split.

PyClause is pinned to commit `87c82ec3dd904767741a493dcbdf7605377d4535` and its shipped AnyBURL JAR is hashed. Three serial20-second attempts use one worker and a512MB Java heap. Admit only same-subject single-body feature implications; independently recount their training evidence and require joint>=5, >=2 source groups, confidence>=0.5 and within-center lift>=1.05. Native sampled learner statistics are retained but are not substituted for the exact recount.

| Arm | Learning / selection | What comparison means |
|---|---|---|
| AnyBURL | Union of three bounded runs, restricted language and exact filters | Learned rule coverage in this language |
| Association shortlist | Same learned rules restricted to top100 unordered training-only FP-Growth pairs | Post-learning shortlist tradeoff, not faster learning |
| Exact counting | Enumerate the same feature implications with the same filters | Whether the stochastic learner recovers the directly countable language |
| Center frequency | Most prevalent unseen feature around the center type | A baseline without conditioning on a second connection |

Every learner receives all training facts. The preliminary all-corpus association catalog is not used to select these rules. Query application uses native PyClause with zero U_c unseen smoothing, known answers filtered, all stopping disabled, and independently checked maximum-confidence scores. The final top-one tie-break is canonical feature text, not native frequency tie ordering.

The secondary typed-port occurrence-edge probe is a separate feasibility question; its infrastructure failure is not a head-to-head prediction score.

### Study D method: separate epistemic status from the next action

The native research assistant authored a deterministic Python diagnostic after an interview and protocol debate. An initial proposal to retrofit intents to corpus groups was rejected: saved wiring alone cannot establish purpose. The final protocol instead uses prospectively authored structured cases and an unchanged pinned native catalog.

| Method | Predicates covered | Output contract |
|---|---|---|
| B0 | Named ports, static type overlap, local type contradictions | PORTS_PASS, PORTS_FAIL or PORTS_UNKNOWN only |
| B1 (primary comparator) | B0 plus unconditional required fields, scoped binding witnesses and local conflicts | FIELDS_PASS, FIELDS_FAIL or FIELDS_UNKNOWN only |
| Ledger | Those predicates plus authored intent and limited authorized revisions | ASK, REJECT_SCOPE, REVISE or SPEC_GROUNDED, with retained blockers and runtime unknowns |

For an edge, declared output types are used when present; otherwise a return annotation supplies an explicitly weaker witness. Compatibility requires nonempty overlap with declared input types. For each required field, a compatible wire or scoped, nonconflicting, synthetic-assumption binding must exist. These predicates do not establish activated ports. Agent.model is required in the pinned catalog; a universal API-key requirement is not inferred.

The implementation processes recognized revisions, then checks the resulting state. Revoke reopens the model obligation; rename preserves scoped references; a uniquely authorized direct-route edit uses an existing Agent. Removal contrary to retained intent asks without applying it. This is not a general transactional planner: pre-existing identity conflicts can still interact unsafely with edits outside the tested cases.

The decision priority is unsupported capability → REJECT_SCOPE; other static blockers → ASK; otherwise applied authorized patch → REVISE; otherwise SPEC_GROUNDED. Runtime obligations remain unknown throughout. The original oracle and protocol disagreed on whether an activation-certification request should be rejected or deferred with a question. That difference is retained, not repaired into a perfect score. Mined rules did not enter this diagnostic, so Study D cannot establish their incremental value.
