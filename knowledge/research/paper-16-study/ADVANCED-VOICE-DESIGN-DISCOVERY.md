# Advanced voice-design discovery — Paper 16

Audited 31 October 2026. **Research only:** official repository/model-card inspection, pinned source snapshots; no installations, model downloads, upstream execution, remote uploads, generation, app edits or service changes. The original request is sophisticated **synthetic voice identity design**, followed by a reusable character asset library—not merely cloning, conversion or another interface.

## Recommendation

**Qualify Qwen3-TTS VoiceDesign → Base first, with the existing VoxCPM2 route as the comparator. Keep VoiceSculptor as the specialist research lead for deeper attribute controls.** No candidate is yet runtime-qualified against our full standard. None of the inspected public interfaces demonstrates a universal, deterministic editor that can turn exact age, rasp, resonance, accent and pitch knobs independently while guaranteeing the same character identity and acting across new words.

Qwen is the best documented fit for the immediate handoff: create a synthetic voice from a rich description, select an actual recording, extract a reusable clone prompt, and reuse it for new lines. The maintainers explicitly document that sequence. VoxCPM2 also combines new-voice design, reference identity and optional style direction, and has already been exercised in our project; its own documentation warns that controllability varies across runs. VoiceSculptor has the most interesting explicit attribute-token surface, but its released UI has substantial CUDA/custom-dependency assumptions and its complete cloning/training release remains incomplete. These are reasons to run qualification, not claims of superior sound. [Qwen design→clone workflow](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/README.md#L288-L354), [Vox modes and controls](https://github.com/OpenBMB/VoxCPM/blob/cce58a5b59303c9bd63d12f23afe6a49a4a80c59/README.md#L145-L191), [Vox stability warning](https://github.com/OpenBMB/VoxCPM/blob/cce58a5b59303c9bd63d12f23afe6a49a4a80c59/README.md#L649-L655), [VoiceSculptor overview/release scope](https://github.com/ASLP-lab/VoiceSculptor/blob/db7aeac78da0c65c328996c4eab9f83295acf708/README.md), [VoiceSculptor implementation](https://github.com/ASLP-lab/VoiceSculptor/blob/db7aeac78da0c65c328996c4eab9f83295acf708/gradio/webui.py#L483-L565).

## The standard a candidate must satisfy

| Gate | Evidence required before adoption |
|---|---|
| **Create identity** | New synthetic speaker without needing an existing actor's identity recording; distinguish this from a preset selector. |
| **Refine honestly** | Document which traits are direct inputs, categorical tokens or probabilistic descriptions. Do not advertise independent numeric controls where none exist. |
| **Hold identity** | Approved recording and reusable speaker conditioning must survive fresh sentences; changing a description alone is not a fixed identity. |
| **Separate performance** | Record whether style/emotion can be controlled while using the saved custom identity. A preset-speaker emotion demo does not prove this. |
| **Integrate and preserve** | Usable source/API, original WAV, transcript, full request, seed/sampling, model/code revisions and reusable prompt/embedding where supported. |
| **Operate and distribute** | Target-platform path and actual measured performance, separate code/weight licences, and an asset export that does not require unrecorded server state. |

A documentation pass admits a project to testing. It is not a listening pass or production qualification. Existing scene/profile work is evidence to reuse, not proof all six gates are solved.

## What sophistication means in the two strongest routes

### Qwen: complete design-to-reusable-identity recipe, with an important boundary

VoiceDesign and Base are **different checkpoints**. The documented reusable prompt contains speaker/reference conditioning, not a model-independent character object. Preserve the WAV and exact transcript as the portable authority, plus the extracted prompt as an engine-specific acceleration asset. Rebuild/version that prompt when the engine changes. `x_vector_only_mode` uses only speaker embedding and drops transcript/code conditioning, with a documented possible quality reduction. It is an experiment, not an unconditional upgrade. [Prompt data structure](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/qwen_tts/inference/qwen3_tts_model.py#L41-L57), [Prompt construction and modes](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/qwen_tts/inference/qwen3_tts_model.py#L356-L458), [Workflow](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/README.md#L288-L354).

Do not merge three marketing capabilities into one nonexistent function: **VoiceDesign** has descriptive instructions; **CustomVoice** has preset speakers plus instructions; **Base** clones a custom reference. The inspected Base API has no explicit `instruct` parameter, and its documented model table leaves instruction control blank. MLX-Audio also explicitly rejects instructions in batched reference cloning. The fact that VoiceDesign can speak angrily does not prove a separately fixed custom identity can be directed that way. [Model matrix](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/README.md#L73-L79), [Base signature](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/qwen_tts/inference/qwen3_tts_model.py#L470-L533), [MLX batching guard](https://github.com/Blaizzy/mlx-audio/blob/7a0986280fe295f4cf40f64164bb23abed416a22/mlx_audio/tts/models/qwen3_tts/qwen3_tts.py#L1774-L1789).

Single-speaker fine-tuning is supplied as a later route, but it requires an audio/text/reference dataset and separate training/evaluation. The official guide recommends keeping the reference consistent across training samples. It does not establish that our laptop can train it efficiently or that one approved audition is enough to create an acting library. [Fine-tuning guide](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/finetuning/README.md#L1-L56).

### VoiceSculptor: meaningful attribute controls, incomplete product handoff

The released UI maps selections into categorical learned tokens for four age bands, two gender categories, five pitch levels, five pitch-variation levels, five volume levels, five speed levels and six visible emotion categories. This is more concrete than a UI that merely concatenates every slider into a prose prompt. However these are **categories**, not numerical guarantees about perceived age, fundamental frequency, resonance or emotional strength. RAG rewrites/retrieves descriptions; it does not demonstrate acoustic latent-vector editing or guarantee preserving a selected character. [Token map and request construction](https://github.com/ASLP-lab/VoiceSculptor/blob/db7aeac78da0c65c328996c4eab9f83295acf708/gradio/webui.py#L492-L552), [Visible controls](https://github.com/ASLP-lab/VoiceSculptor/blob/db7aeac78da0c65c328996c4eab9f83295acf708/gradio/webui.py#L630-L670).

The design component writes a 16 kHz WAV; inference samples tokens. The standalone example selects CUDA or CPU, not Metal. The WebUI imports vLLM, hard-codes workers on CUDA devices and uses custom CosyVoice signatures. Its README still marks cloning code and training code as unreleased even though the UI contains downstream integration calls. An English description guide is not proof of English speech quality: the example/model name and reported evaluation are Chinese-focused. This makes it valuable to learn from and audit further, but not a drop-in production choice for our M3 Max. [Standalone script](https://github.com/ASLP-lab/VoiceSculptor/blob/db7aeac78da0c65c328996c4eab9f83295acf708/infer.py#L30-L88), [CUDA workers](https://github.com/ASLP-lab/VoiceSculptor/blob/db7aeac78da0c65c328996c4eab9f83295acf708/gradio/webui.py#L243-L270), [UI startup/dependencies](https://github.com/ASLP-lab/VoiceSculptor/blob/db7aeac78da0c65c328996c4eab9f83295acf708/gradio/webui.py#L483-L565), [Release checklist](https://github.com/ASLP-lab/VoiceSculptor/blob/db7aeac78da0c65c328996c4eab9f83295acf708/README.md), [Description guide](https://github.com/ASLP-lab/VoiceSculptor/blob/db7aeac78da0c65c328996c4eab9f83295acf708/docs/voice_design_en.md).

## Smallest useful qualification, when generation is authorised again

1. **Design adherence:** freeze one character brief with three audible identity traits, and use the same neutral audition sentence. Produce three candidates with Qwen and three with existing Vox; preserve all requests and seeds. Blind-listen for intended traits and words. Never infer exact age from a label.
2. **Identity handoff:** choose one actual design recording from each, build the documented reusable conditioning, and speak three unseen sentences. Replay after a fresh process/load. Check identity stability, words, artifacts and actual memory/time on this Mac. A description alone is not the saved identity.
3. **Refinement test:** change only one trait (for example perceived pitch) while holding script/seed/settings fixed. Treat the result as a new identity candidate; retain the previous one. Test whether other approved traits drift. Do not promise an in-place edit if the engine regenerates.
4. **Performance is a separate gate:** only after identity reuse works, test delivery guidance on the same fixed identity with two contrasting styles and new words. Record which native mode actually accepts those controls. If it requires another engine or a new reference, expose that fact and retest identity.
5. **Promote only demonstrated assets:** save approved WAVs, transcripts, exact methods and model-specific reusable conditioning into the character library. Experimental designs remain visible without being qualified for production.

No new installation is required to co-design the interface. Keep the first identity screen engine-neutral: brief → audition candidates → selected immutable recording → reuse check. Show native controls only when the chosen engine supports them, and keep desired traits distinct from measured/listener-confirmed traits. Do not add a universal emotion/intensity slider to conceal incompatible APIs.

## Scope and remaining unknowns

- The comparison concerns seven projects, not an exhaustive survey of all published research.
- No candidate's English voice quality, identity persistence, age/accent adherence or acting has been independently listened to during this discovery. Public benchmark tables are authors' evidence, not our acceptance results.
- M3 Max / 64 GB is a reasonable qualification target for the Qwen MLX route and the already-used Vox route, but model size and an implementation do not prove latency, memory headroom or feature parity. Load checkpoints sequentially when authorised; do not infer CUDA benchmark speed on Apple Silicon.
- There is no proven requirement to adopt a new engine. Qwen must outperform or add a verified capability beyond existing Vox; VoiceSculptor's specialised controls must justify its port/integration cost.
- No Docker, contract services, existing UI or notebook state was changed by this research worker.
